# What's new in v0.3.0

Experimental PRO 2 support, better connection recovery and more reliable refill tracking.
Big thanks to **[kbaker827](https://github.com/kbaker827)** for
[pull request #12](https://github.com/loryanstrant/HA-HidrateSpark-Bluetooth-Proxy/pull/12),
including the new regression tests. The original contribution and commit authorship are preserved.

## Added

- **◐ Experimental PRO 2 support:** follows advertised bottle names across Bluetooth
  address changes, checks available characteristics and recovers quiet connections.
  Not yet verified on PRO 2 hardware; please report your model, firmware and results.
- Fill and refill detection from usable sip-record weights, including refills missed
  by cap notifications. A per-bottle weight scale is learned from recorded sips.
- Model and firmware details where the bottle provides them.

## Fixed

- The bottle-capacity options no longer fail when opened on current Home Assistant.
- Existing bottles retain their device/entity identity during migration; entering a
  known address manually does not create a second bottle.
- Empty fill and refill deduplication survive restarts. Rejected or unusable weight
  samples no longer change calibration or fill.

## Upgrade notes

Requires Home Assistant 2024.12 or later (unchanged HACS minimum). Existing entries
migrate automatically; do not delete/re-add a working bottle to upgrade. Pre-existing
duplicate entries are not merged automatically. Check which one owns your history
before deleting any permanently unavailable duplicate.

Real-bottle checks are still outstanding for PRO (v1) upgrade/history, PRO 2
rotation/reconnects, and legacy 32oz sip-weight bytes. Observed sip records do not
include a drink timestamp: buffered sips are timestamped when received.

## Release preparation (not published)

Merge and publishing each need separate approval. After merge: create the tag and
release on Gitea first, sync the mirror, confirm the tag on GitHub, then publish on
that existing tag. Never create a GitHub-only tag or merge the GitHub PR.
The prepared `hidratespark_bluetooth_proxy.zip` contains the integration-directory
contents at its root, exactly as `.github/workflows/release.yaml` packages them.
HACS currently uses the repository tree (`zip_release: false`); validate both layout
and manifest before publication. Published-release installation is a later gate.
